# Stream Machine plugin UX plan

Status: proposed product direction, awaiting user choices. This task changes documentation only. [Issue #81](https://github.com/prime-optimal/stream-machine-plugin/issues/81).

## Product direction

Open Stream Machine as a compact working studio. Give each task its own view, retain context beside the conversation, and ask for setup only when the selected task needs it.

Primary navigation: Home, Assets, Clips, Stream Deck, and Connections. Recipes appear on Home and inside the relevant workspace; a recipe browser is secondary navigation. Keep current Twitch title, OBS test, and automation controls under Tools until each has a natural home. Move the fictional demo to an explicit Mock demo route.

A global sidebar entry opens Home. The thread entry opens a focused workspace alongside the current conversation. Inline results summarize one selected clip, asset, connection check, or completed action and offer Open workspace. Keep server tools usable when the host cannot render the app.

### Visual character

Use ChatGPT's spacing, type, light/dark theme, focus treatment, safe areas, and control styles. Reserve strong color for primary actions, selections, and meaningful status. Let clip thumbnails and generated artwork supply most visual variety. Replace the landing page's large marketing headline with a compact view title and one primary action.

On wide views, use a narrow navigation rail, a working area, and a selection inspector. On narrow views, use a labeled navigation menu, single-column cards, and a full-width detail view with Back. Avoid three columns inside a narrow conversation panel. Keep the same routes and vocabulary across sizes.

Each view has a stable heading, account or device context, primary action, and content area. Details and diagnostics expand on request. Never expose request UUIDs or exact project IDs as the normal way to operate; retain them in diagnostic details and recovery.

Support keyboard navigation, visible focus, screen-reader labels, non-color status text, and reduced motion. Pause media when its view closes. Never autoplay audio. Announce job progress without stealing focus.

### View composition

| View | First screen | Selection or editing area | Primary outcome |
| --- | --- | --- | --- |
| Home | Three task cards, compact connections strip, recent work, running jobs | Recommended recipes with thumbnails and prerequisites | Start a task or resume work |
| Assets | Project picker, recent assets, recipe cards | Brief on the left; large preview on the right; output/version inspector | Generate, inspect, revise, and export an asset |
| Clips | Account/channel header, filters, thumbnail gallery | Player plus metadata; download/export actions | Find, inspect, and save a clip |
| Stream Deck | Device/profile selector, current configuration with source label | Device-shaped grid, selected key inspector, recipe previews | Compare a layout and apply an explicit change |
| Connections | Provider list with last-check status | Task-specific setup and troubleshooting | Verify a dependency and return to the task |

These are target experiences. The initial release exposes only verified capabilities. The detailed contracts below explain the smaller first slices.

## Assets experience

The workspace supports overlays, images, and eventually videos without pretending every output is available now. Filter the library by project and output type. Asset cards show thumbnail, name, format, dimensions, duration when relevant, version, creation time, and generation state.

Start with a recipe or a blank brief. The proposed brief captures purpose, canvas size, text, brand colors/fonts, reference images, and motion preference. Reuse project defaults but show overrides. Before generation, show output type, destination project, and any known cost or limit. Do not invent a price estimate.

The preview offers Play/Pause/Replay for animation, a transparency background toggle, fit/actual-size controls, and a safe-area overlay. Inspect a static image at stream and thumbnail sizes. Preview generated HTML in an isolated viewer or a provider preview, never inside the privileged app document.

Actions remain distinct: Generate, Revise, Download source/package, Open preview, and Use in OBS. A successful generation does not mean an overlay was installed in OBS. If embedding fails, use a poster and external preview with an explanation.

First working slice reuses the existing static overlay and HyperFrames HTML recipes. The current adapter has a constrained title field and a fixed QA scenario; a full brief, image generation, video rendering, revision history, and a persistent asset library require additional provider work. Video is an optional later slice with format, duration, alpha, audio, size, rendering-cost, and playback acceptance defined first.

## Clips experience

Target gallery: account/channel picker, date range, category, sort order, and search above a responsive thumbnail grid. Selecting a card opens a player and metadata inspector without starting a download. Preserve filters and scroll position on return.

Each card shows thumbnail, title, duration, category, clipper username, and creation time. The inspector adds broadcaster, source link, view count if available, download state, and optional transcript. Distinguish clip creation time, offset within the source stream, and download completion time. Show Unavailable for missing metadata; never substitute one timestamp for another.

The player supports seeking, volume, keyboard controls, poster image, loading/buffering, unavailable/deleted source, and expired-media recovery. Images use the same selection/detail pattern. Play only one clip at a time. An image-only fallback must not be labeled a playable clip.

First slice accepts one authorized clip ID and proves metadata, thumbnail, player, and download in a named host. Category and clipper fields are required parts of the target design. Add `gameId`, `categoryName`, `creatorId`, and `creatorName` where supported; resolve the category through the existing game work once merged, or show its unknown state. A nullable stream-offset field is separate from creation time.

Then add channel listing, pagination, filtering, and a saved collection. Batch download waits until one-record behavior works and has per-item progress, cancellation, limits, and partial-failure handling. Cross-channel file downloads remain unavailable under the current ownership policy.

The initial collection is explicitly labeled This session. A durable library needs account-scoped records, retention/deletion controls, storage quotas, and reopen behavior. Shared cross-device storage is an unanswered product decision, not implied by a web gallery.

## Stream Deck experience

The intended view pairs the selected device's grid with an inspector and a recipe strip. Clearly label the source of every displayed layout: native Elgato profile, Stream Machine page, proposed recipe, or unknown. Never draw blank keys as proof the physical device is empty.

Target comparison shows current and proposed keys, additions/replacements, device compatibility, required integrations, and unsupported actions. Selecting a recipe creates an editable draft. It does not take USB ownership or write a profile. Changes invalidate previous approval.

First slice remains the supported Original 3×5 device and separate USB test page. Native Elgato profile inspection/editing requires a new integration decision. Show the limitation directly beside the selector. Keep a visible Release device action and explain that button handling needs the keeper process.

Later recipe examples include an OBS scene page, clip-review shortcuts, and a stream-preparation page. Mark these Planned until their actions and device models work. A layout package/export is a separate capability from applying it live.

## Contextual onboarding

Use the plugin's Onboarding skill for the first conversation and discovery. Use in-view setup for the specific dependency that blocks the chosen task. Native settings are appropriate for simple preferences; Connections owns multistep setup. Never force Twitch, OBS, OpenDesign, and Stream Deck setup before the first useful action.

A connection badge means a verified capability, not merely stored credentials. Show the account/device, granted capability, last checked time, and Recheck. Distinguish Not checked, Setup needed, Checking, Ready, Access expired, Unreachable, and Unsupported here.

### Twitch flow

Choose a clip task, preserve its draft, inspect current account/grants, explain the missing permission, and open the existing OAuth flow. After returning, re-read the authenticated profile and required scope before resuming. A browser closing or a redirect occurring does not prove authorization.

Show which account connected and let the user switch accounts. Account changes invalidate previews and clear account-bound selections/media. Handle refusal, canceled popup, stale redirect, expired grant, wrong broadcaster, missing clip scope, and provider outage separately. Never request secrets in chat. Keep title-update approval separate from clip access.

Capture macOS first as a proposal; Windows remains a user choice. Record OS, OBS build, host build, capture date, and source files under `docs/onboarding/obs/<platform>/`. Use numbered screenshots with alt text as the baseline. Add a short replayable animation only where motion helps; provide still frames for reduced motion. Never capture Show connect info, passwords, QR codes, unrelated windows, or real stream content.

The connection test reads version, scenes, and output status. It must not start/stop streams or recordings, change scenes, or trigger alerts. Show authentication failure, connection refused, OBS not running, unsupported protocol, timeout, and host-locality failure with distinct next steps. Do not advise disabling authentication.

The current fixed OBS client has authentication/configuration limitations. Supporting normal authenticated setup is a provider prerequisite; a polished guide cannot compensate for a client that cannot use the user's settings. Secure host/port/credential input and storage need an explicit implementation slice. On web, explain whether a reachable local connector is missing; an iframe cannot be assumed to control the user's OBS.

A later visible overlay test requires explicit user action and safe Preview-only verification. Preserve program/broadcast state and verify cleanup. Current alert behavior can select a program scene, so it is unsuitable as the automatic setup check.

- `stream_machine_open` advertises global entrypoint; `stream_machine_workspace` advertises thread entrypoint. Both return mock workspace snapshots and same app resource.

- `src/preview-bridge.ts` forwards discovered MCP tools through separate stdio child.

**Correction:** fictional workspace currently lives in collapsed `<details class="mock-workspace">` on same page. It is not routed.

### UI ownership and mutation

`app.ts#render()` replaces root HTML, then reattaches one persistent `liveDemos` DOM subtree. Mock state lives in module variables; live state lives in closures inside `createLiveDemos()`.

`live-demos.ts` supplies:

- Per-card pending flag.
- App-instance-wide mutation flag.
- Transient title/deck preview IDs.
- Creative request UUID retained after submission.
- Generic allowlisted text summaries.
- Direct external anchors for connection and preview URLs.

Generic summaries omit clip metadata, discard result identity, and cannot support galleries or contextual recovery. Root replacement also risks focus loss and complicates independent workspace lifecycles.

### 3.2 App state and lifecycle

Replace monolithic rendering with persistent shell and independently mounted view controllers.

Partial interface shape:

> View controller: `element`, `activate()`, `deactivate()`, `dispose()`.

- Shell owns route, host adapter, transport, mutation coordinator, session recent-work references.
- Each workspace owns drafts, selected item, result state, and request revision.
- Controllers created lazily, retained until app disposal.
- Navigation preserves drafts and pending-operation identity.
- Navigation does not release USB, stop worker, or cancel provider writes.
- Deactivation pauses local media and stops scheduled polling.
- Disposal clears timers, event listeners, and object URLs.

Use explicit request states:

`idle | loading | ready | failed | outcome_unknown`

Results retain previous successful data on failed refresh, marked **Stale: refresh failed**.

For reads, increment request revision; ignore older responses. For writes, capture immutable inputs before dispatch and always record completion against original operation, even after navigation. Never automatically retry dropped/ambiguous writes.

App mutation coordinator serializes explicit live actions across views. Read checks remain available except when same component contract forbids concurrency. This coordinator is UX protection, not cross-process locking.

Host-originated tool results pass through workspace-specific Zod parsers. Unrelated or malformed results cannot overwrite active selection. Existing provider services remain final authorization authority.

### 3.5 Bounded clip preview delivery

**Candidate A for a local-only prototype, not an approved media architecture:** transfer bounded completed artifacts through app-only MCP reads. First compare this with a supported host media resource and authenticated HTTP range delivery. The selected method must support the target web deployment and prevent cross-account access. Chunking does not solve local stdio reachability from a browser. The bounds below are provisional experiment limits, not Twitch or ChatGPT limits.

Add process-owned `ClipArtifactAccess`:

- Registers completed `ClipArtifact` records.
- Stores opaque artifact UUID, owning principal/account, session binding, validated path, bytes, and hash.
- Never accepts caller-supplied paths.
- Authorizes every read against the current principal/account and session. A UUID is not authorization. Disconnect, account switch, or session expiry invalidates handles and clears client buffers. Test cross-account reads from two app instances.
- Only artifacts completed by this server process are eligible.
- Registry lifetime equals MCP server lifetime in this candidate; restart invalidates preview handles while the local file remains. Prefer reopening a validated library record over requiring a duplicate download. Persistent reattachment is a later library contract, not existing behavior.

New app-only tool:

> `stream_machine_twitch_clip_artifact_chunk({artifactId, offset})`

Contract:

- UUID artifact ID.
- Nonnegative integer offset aligned to 256 KiB.
- Maximum 256 KiB per response.
- Preview eligibility capped at **32 MiB**.
- Response metadata: artifact ID, offset, total bytes, EOF.
- Base64 bytes delivered in app-only result metadata, not model-visible text/structured content.
- Read-only annotation; UI visibility only.
- Reject unknown IDs, unsafe/missing/changed files, invalid offsets, oversized previews.
- Open files without following symlinks; require regular private owner-owned file and expected size.
- Close each file handle after chunk read.

UI retrieves chunks serially on explicit Load preview, checks continuity/size, verifies SHA-256 against completed artifact, then creates `video/mp4` Blob URL. One loaded Blob per app instance. Selection change, deactivation, replacement, or disposal revokes URL and clears buffers.

Over-limit artifact shows local-file fallback, not failed download. Cancellation stops requesting further chunks; completed server file remains untouched.

Security constraints:

- Do not expose arbitrary filesystem access.
- Do not forward Twitch authorization to artifact reads.
- Do not put bytes into model context or recent-work records.
- Do not widen global CSP to wildcard domains.

**Validation gate:** confirm installed MCP/App SDK preserves app-only metadata and supports Blob media under host CSP. If unavailable, ship metadata/local-file workflow with preview explicitly unavailable. Do not claim complete clip acceptance until supported host plays real downloaded media. No silent alternate media server.

Standalone preview bridge must preserve chunk metadata. Existing `/api/tool` same-origin protections remain intact.
