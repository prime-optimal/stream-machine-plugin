# Complete the Site clip gallery

Issue [#218](https://github.com/prime-optimal/stream-machine-plugin/issues/218) extends the save-action work in [PR #211](https://github.com/prime-optimal/stream-machine-plugin/pull/211).

## Outcome

One Play action saves an unsaved clip to the existing Site, then plays its Site URL.
Already stored clips play without another archive request.
Prepare all discovers a bounded set, asks the user to confirm that set, and processes clips serially with progress and cancellation.

## Existing pipeline

The hosted source already obtains the Twitch download URL, writes bytes into R2, records completed D1 metadata, and serves a Site media URL.
A real saved KLabFM clip returned HEAD 200, Range GET 206, and played in the in-app browser at 1280 by 720.
The initial playback problem did not establish a codec or range-serving defect.

The client discarded archive metadata and rescanned ten pages after saving.
PR #211 made the save control visible but retained that extra lookup and separate Play action.

## Changes

- Add authoritative stored metadata to saved and skipped archive results without removing existing fields.
- Classify failed post-write confirmation as unknown. Never blindly repeat that write.
- Consume the returned Site URL directly, with an exact origin and file-route check.
- Share one preparation request between duplicate Play actions and bulk work.
- Guard detail, account, and status lifecycles against late responses.
- Keep native video controls, seeking, teardown, and a visible Play fallback after autoplay denial.
- Discover at most ten pages and prepare at most 100 unsaved clips per confirmed batch.
- Stop future dispatch on Cancel while allowing an accepted request to report its final outcome.
- Serve the same bundle at the Site's /clips page through a narrow authenticated /api/tool bridge.
- Require trusted Sites identity and same-origin requests. An unsigned owner cookie is insufficient.
- Publish a new MCP UI resource version after syncing the plugin bundle into the Site.

## Ownership

The plugin branch owns src/ui/clips*.ts, the app integration, fixture, tests, and checked state models.
The independent Site source owns archive metadata, /clips, /api/tool, and the generated UI bundle.
Existing source identity and public access policy remain unchanged.
No Twitch broadcasts, OBS state, or Stream Deck state change.

## Validation

Regressions cover dropped metadata, uncertain saves, duplicate calls, cancellation, account changes, stale status responses, and the browser API authorization boundary.
Browser checks cover one-click preparation, advancing playback, seeking, teardown, and per-item bulk failures.
Synthetic saves remain labeled as fixtures.
Live acceptance requires one real archive before preparing the remaining channel clips, followed by a fresh library read.

The [state model](../statechart/primary-navigation/clips/library/README.md) distinguishes checked rules from browser and provider evidence.
The [review record](../reviews/218-clip-gallery.md) records actual outcomes and limits.
