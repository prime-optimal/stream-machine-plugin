### Server composition and lifecycle

### Local preview: actual MCP tool calls

Flow:

`browser → same-origin /api/tool → MCP client.callTool → dist/server.js → registered handler → MCP result → browser`

Behavior:

- Spawn bundled server using `process.execPath`; resolve server path independently of caller working directory.

- Route child diagnostics to stderr, not API responses.

- No second adapter dispatcher or direct mock dispatcher.
