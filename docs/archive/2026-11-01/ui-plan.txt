# 3. Design

## A. Transport and response ownership — `app.ts`

Extract existing transport branch into internal asynchronous function:

- New interface: `requestTool(name, args): Promise<ToolResult>`.
- Sends exactly one request.
- Standalone checks HTTP status and parses JSON.
- Native calls existing bridge.
- Performs no rendering, mock acceptance, context updates, or retries.

Keep existing mock `call(name, args): Promise<void>` interface and callers unchanged. It uses `requestTool()` but retains mock draft capture, busy state, reset semantics, errors, and context updates.

Pass `requestTool` into live controller. Live actions never pass through mock `call()`.

### Routing

Replace unconditional host-result acceptance with explicit classification:

1. Structured `mode === "mock"` plus error: handle existing mock error.
2. Structured `mode === "mock"` plus snapshot: existing `accept()`.
3. Recognized live result: live controller’s passive result handler.
4. Anything else: ignore; do not replace mock snapshot.

Direct live-call errors belong to initiating card even when standalone backend returns `{ mode: "mock", error: { code: "UNKNOWN_TOOL" } }`. Transport caller determines ownership before inspecting result mode.

Unsolicited host live results may update safe display summaries only. They must not authorize apply, replay, run, release, or arm actions.

## B. Live controller — `src/ui/live-demos.ts`

Use module-level types and one controller factory; no framework or provider registry.

Partial interface:

```ts
createLiveDashboard({ requestTool, invalidate, escape })
  → { render, bind, captureDrafts, acceptHostResult, dispose }
```

- `render()` returns escaped dashboard markup.
- `bind(container)` attaches listeners after parent render.
- `captureDrafts(container)` saves current control values.
- `invalidate()` requests parent render.
- `acceptHostResult()` accepts recognized, display-only summaries.
- `dispose()` clears polling timers and invalidates pending completions.

`app.ts` creates one controller instance. Helper imports no SDK and owns no host connection.

### Owned state

Five cards: `obs`, `deck`, `twitch`, `creative`, `worker`.

Each owns:

- Phase: `idle | pending | ready | unavailable | unsupported | error | uncertain`.
- Current operation, sanitized summary, typed drafts.
- Operation generation counter for stale-response rejection.
- Validated target identifiers and prerequisite results.
- Local confirmation state tied to exact current target and inputs.

Controller also owns global mutation lock: at most one live write request in flight. Reads on unrelated cards remain allowed. Same-card operations remain serialized.

No local storage, cookies, credentials, or persisted approvals.

Before every parent rerender, capture mock and live drafts. Render itself must not initiate requests.

### Proposed tool contract

Centralize exact names and argument construction in helper. These names are assumptions requiring parent-adapter validation.

| Action | Tool | Arguments |
|---|---|---|
| OBS preflight | `stream_machine_obs_preflight` | Empty |
| OBS alert replay | `stream_machine_obs_alert_replay` | `targetId`, `alertId` from validated preflight |
| Deck inventory | `stream_machine_streamdeck_inventory` | Empty |
| Deck preview | `stream_machine_streamdeck_preview` | Selected `profileId`, `actionId`, `slotId` |
| Deck apply | `stream_machine_streamdeck_apply` | Validated `previewId` |
| Deck release | `stream_machine_streamdeck_release` | Validated `leaseId` |
| Twitch connect | `stream_machine_twitch_connect` | Empty; initiates existing authorization flow only |
| Twitch status | `stream_machine_twitch_status` | Empty |
| Twitch title preview | `stream_machine_twitch_title_preview` | Validated `accountId`, trimmed `title` |
| Twitch title apply | `stream_machine_twitch_title_apply` | Validated `previewId` |
| Creative project | `stream_machine_creative_project` | User-entered `projectId`; lookup only |
| Creative run once | `stream_machine_creative_run_once` | Validated `projectId`, `kind`, trimmed `brief` |
| Creative poll | `stream_machine_creative_run_status` | Validated `runId` |

Creative `kind` has exactly two values: `asset | hyperframes`.

No arbitrary tool-name input, arbitrary argument editor, alias fallback, or direct provider forwarding.

### Live result contract and normalization

Recognized envelope:

- `mode: "live"`.
- `demo: "obs" | "streamdeck" | "twitch" | "creative" | "worker"`.
- Operation-specific known fields.

Treat `structuredContent` as untrusted `unknown`. Validate plain records, bounded strings, enum values, booleans, finite numbers, arrays. Never spread provider objects into UI state.

Distinguish:

- Recognized safe fields present: show partial summary.
- Required prerequisite fields absent: show summary, disable dependent action.
- Successful but unrecognized response: “Unsupported adapter response.”
- Unknown/missing tool: “Adapter unavailable in this checkout.”
- Other tool/transport failure: fixed local error copy.
- Ambiguous write outcome: `uncertain`; require explicit status refresh, no retry.

Do not display provider `content`, raw error messages, raw JSON, HTML, tokens, headers, connection URLs, or generic metadata.

Allowlisted summary fields:

| Card | Fields |
|---|---|
| OBS | Connection enum, target/source name, `targetId`, `alertId`, `safeToReplay`, replay outcome |
| Deck | Bounded profile/action/slot lists, test-profile flag, preview ID, target labels, application-interruption flag, lease ID, applied/released outcome |
| Twitch | Connection enum, account ID/display name, `canManageTitle`, current title, preview ID, proposed title, optional expiry, applied/readback title |
| Creative | Project ID/name, isolated-project flag, run ID/status, artifact name/type, duration, width, height |
| Worker | Worker ID, configuration ID, state, readiness flag, target label, heartbeat timestamp |

Limit lists to 20 entries; labels to 160 characters. Titles max 140, briefs max 2,000. Reject overlong identifiers rather than truncating identifiers used in requests.

Render labels through shared escaping. No provider HTML or provider-derived links. Artifact summaries show metadata only.

## C. Card behavior

### OBS

- Initial button: **Check OBS**. No startup preflight.
- Enable **Replay test alert** only after explicit preflight returns `safeToReplay: true`, `targetId`, `alertId`.
- Confirmation names dedicated test source and alert.
- Replay sends one request, then invalidates replay readiness. Another replay requires new preflight.
- Never expose broadcast, recording, scene-switch, arbitrary text injection, or automation-start controls.

### Stream Deck

- **Load inventory** explicitly reads profiles, installed actions, eligible slots.
- Only profiles explicitly marked test profiles can become write targets.
- Selection changes invalidate previous preview and confirmation.
- **Preview button** performs no device/profile write.
- Preview summary names profile, slot, action and whether Elgato must quit/restart.
- **Apply preview** requires explicit acknowledgment of exact target and interruption.
- **Release** appears only for validated lease ID; separate confirmation explains release affects adapter-held test-session resources.
- Never offer profile deletion, arbitrary scripts, or active-profile modification.
- Missing test-profile/interruption/lease semantics disables corresponding unsafe action rather than inferring safety.

### Twitch

- **Connect Twitch** explicitly starts existing provider flow; no token, password, client-secret, or OAuth-code inputs.
- UI does not navigate to arbitrary returned URLs. If adapter requires browser authorization unavailable through host-managed flow, show “Complete existing Twitch authorization, then refresh status.”
- **Refresh status** establishes account and title permission.
- Title edit invalidates prior preview.
- **Review title** requests read-only preview.
- Approval summary shows exact account, old title, proposed title.
- **Approve title change** requires fresh preview, unchanged draft/account, explicit checkbox, unexpired preview when expiry supplied.
- After apply, show returned readback only when supplied. Otherwise show “Submitted; refresh status to verify.” Never claim verified change from submission alone.

### Creative

- Project ID field plus **Load project**; never automatically create projects.
- Run enabled only for explicitly isolated test project.
- Select asset or HyperFrames, enter brief, then confirm **Run once**.
- One click sends one run request; never auto-resubmit after timeout.
- Valid run ID enables **Check run** and optional **Start polling**.
- Polling requires explicit click; read-only status request every five seconds, scheduled after preceding request settles.
- Stop polling on terminal status, first error, ten minutes, page hide, or explicit **Stop polling**.
- Run statuses: `queued | running | succeeded | failed | cancelled`.
- No run-cancel control unless backend contract later adds one.

### Worker

- **Refresh worker status** first.
- Arm requires validated worker/configuration IDs, explicit readiness and target summary.
- Separate confirmed **Arm**, **Pause**, **Stop worker** controls.
- Label stop “Stop worker — not OBS broadcast.”
- State-specific availability:
  - `paused`: arm.
  - `armed`: pause or stop.
  - `stopped | unknown`: no mutation; refresh only.
- Never auto-arm on load, reconnect, successful status, or creative completion.

## D. Concurrency, failures, lifecycle

All state updates occur on browser event loop.

- Each operation captures generation and relevant IDs/drafts.
- Ignore responses from obsolete generations; poll results cannot overwrite newer mutations.
- No write retries, including network failures.
- Lost write response marks uncertain outcome and clears confirmation.
- Read failures preserve previous summary but mark it stale; stale prerequisites cannot enable writes.
- Missing adapter disables actions in that card; explicit **Retry availability** reruns its safe read.
- Mock Reset affects mock workspace only; does not release Deck resources, pause worker, disconnect Twitch, or clear live results.
- `pagehide` disposes timers. In-flight writes may still complete server-side; never imply cancellation.
- Editing controls during unrelated activity preserves drafts. Same-card pending operation disables its controls.
